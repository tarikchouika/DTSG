# تشغيل الاختبارات محلياً (دليل سريع)

## المتطلبات
- Node ≥ 22.12 (يستخدم `node:sqlite` التجريبي)
- المتصفح: كروميوم 143 مُهيّأ عبر `scripts/prepare-browser.sh` (مرة واحدة)
  ```bash
  bash scripts/prepare-browser.sh
  ```

## تشغيل الخادم (وضع الاختبار — مطلوب لاختبارات E2E)
اختبارات المتصفح تُنشئ مستخدمين مؤقتين عبر `/api/register` وتفتح غرفاً برهان.
خادم الإنتاج يقفل التسجيل (للمشرفين فقط) — لذا للاختبارات المحلية شغّل بوضع الاختبار:
```bash
DM_TEST_MODE=1 node --experimental-sqlite server.js
```
ما يفعله `DM_TEST_MODE=1` (في server.js فقط، لا أثر له في الإنتاج):
1. يفتح `/api/register` للتسجيل الذاتي.
2. التسجيل يفتح جلسة تلقائياً (سجّل = ادخل).
3. المستخدم الجديد يبدأ برصيد 100,000 (لأن الغرف تتطلب رهاناً إلزامياً + رسم افتتاح).

بدون `DM_TEST_MODE` يبقى السلوك الإنتاجي: تسجيل المشرفين فقط، بلا جلسة تلقائية، رصيد 0.

## تشغيل اختبار
```bash
# محركات (بدون متصفح):
node tests/_dama_engine_test.js
node tests/_chess_engine_test.js
node tests/_parchisi_engine_test.js

# متصفح (يتطلب الخادم بوضع الاختبار + chromium):
LD_LIBRARY_PATH="$PWD/node_modules/.chromium-143/al2023/lib" node tests/_dama_browser_test.js
LD_LIBRARY_PATH="$PWD/node_modules/.chromium-143/al2023/lib" node tests/_rn_mp_test.js
```
كل الاختبارات في مجلد واحد: `tests/` (باسم `_*.js`) — لا ملف اختبار في جذر المستودع.

## لماذا إصلاحات api.js / index.html / live-ws-bridge.js؟
- **`js/core/api.js`**: في الإنتاج الواجهة (Pages) تستهلك Worker خارجي (`*.workers.dev`).
  محلياً يتجه `API_BASE` إلى `location.origin` (server.js يخدم API وواجهة معاً) — وإلا فشلت كل طلبات API.
- **`index.html` + `js/core/live-ws-bridge.js`**: جسر WebSocket (Durable Objects) خاص بالـ Worker.
  محلياً server.js يدعم SSE فقط، لذا لا يُحمَّل الجسر ويبقى `EventSource('/api/live')` الأصلي.

## ⛔ تحذير سلامة مُلزِم — اختبارات الغرف والمال تكتب في الإنتاج إن شُغّلت كما هي

> **على هذا الهاتف المنفذ 3000 هو خادم المنصة الحيّ (pm2 `casino-server`).**
> عدة اختبارات غرف/مال كانت تثبّت `BASE` على `http://localhost:3000/` مباشرة.
> تشغيلها بلا تعديل **يفتح قاعدة الإنتاج** `data/royalcoin.db` فيُسجَّل فيها:
> مستخدمون اختبار · غرف اختبار · وصفوف `bet` و `win` و `refund` **في السجل المالي الحيّ**.
> لا تشغيل لها على 3000 إطلاقاً.

### الطريقة المدعومة: `QA_BASE` + خادم معزول

منذ v2.69.1 اختبارات الغرف/المال تقرأ عنوانها من [`tests/_safe_base.js`](../tests/_safe_base.js):

```js
const BASE = require('./_safe_base.js').BASE;   // أو { host, port }
```

سلوكها:
- `QA_BASE=http://127.0.0.1:3971/` ⇒ يعمل على الخادم المعزول بلا تحذير.
- بلا `QA_BASE` ⇒ يعود للقيمة التاريخية (المنفذ 3000)، **لكنه يرفض التشغيل (خروج 2)** إن كان ذلك المنفذ مربوطاً بخادم المنصة الحيّ (يكشفه pm2).

```bash
# خادم معزول (يقلع نسخة بقاعدة مستقلة) ثم الاختبارات
QA_BASE=http://127.0.0.1:3971/ node tests/_bet_settle_v269_test.js       # 46 — عقد المال v2.70 (رسم 5% من الجرة)
QA_BASE=http://127.0.0.1:3971/ node tests/_rm_guard_settle_v270_test.js  # 16 — متصفحان: حرس الدور/المرسل + تسوية رامي + إعدادات الغرف
```

اختبارات تستخدم `QA_BASE`: `_rooms_v267_test` · `_rooms_isolation_v268_test` · `_bet_settle_v269_test` ·
`_rm_guard_settle_v270_test` · `_resilience_test` · `_req678_test` · `_req3_test` · `_dama_settle_test` ·
`_rn_bet_test` · `_rn_settle_test` · `_v262_pro_test` — إضافةً `tests/_rd_pw.js` (المستعمل في اختبارات المتصفح) يأخذ `QA_BASE` أيضاً.

**ملفات ما زالت تشترط انتباهاً خاصاً** (لا تقرأ `QA_BASE`):
- `tests/_audit_remediation_test.js` — `BASE` مثبَّت على `http://127.0.0.1:3000` (السطر 16) ولا يقرأ `QA_BASE` ⇒ لا تشغّله ما دام المنفذ 3000 مربوطاً بالخادم الحيّ؛ وجّهه إلى خادم معزول (بتعديل ذلك السطر) قبل تشغيله.
- `tests/_ops_guards_test.js` — `QA_PORT` من `process.env.OPS_QA_PORT` وافتراضيه **3000** ⇒ شغّله فقط بـ `OPS_QA_PORT=39xx` (السكربت يقلع خادمه بنفسه على منفذين: `OPS_QA_PORT` و `OPS_NOMODE_PORT`).
- الملفات المعزولة ذاتياً (خادم تيليغرام وهمي + قاعدة في الذاكرة) آمنة: `_support_bot_test` · `_financial_bot_test` · `_financial_bot_db_test`.
- الثابتة بلا خادم أصلاً: `_repo_hygiene_test` · `_deploy_coverage_test` · `_leave_btn_static_test` · `_catchup_test`.

### العدّاء المجمّع للمؤلف

```bash
bash tests/_run_regression_rooms.sh
```
يشغّل خادماً معزولاً في `/tmp/dtsg-rooms-qa` على `QA_PORT` (افتراضي **3971** — لا 3000 أبداً)، يرفض التشغيل إن كان المنفذ مربوطاً بخادم المنصة الحيّ (pm2)، ثم يجري أجنحة الغرف/الأمان/النشر ويطبع المجموع. يعمل مع `QA_PORT` و `QA_DIR` و `QA_NODE_MODULES` كمتغيّرات. Failing واحد معروف في `_req3_test` («لوحة المتفرج» الموروث من v2.68) يُعرض ولا يُحسب في الفاشل.

> **`node_modules` شرط لأجنحة المتصفح/المحرك.** النسخة المعزولة تُستثنى من النسخ،
> و`require()` لا يصعد من `/tmp` إلى المستودع ⇒ `MODULE_NOT_FOUND` بلا `node_modules`
> (وهو خطأ بيئة لا انحدار). يُربط تلقائياً من `$REPO/node_modules`، أو حدّده صراحة:
> `QA_NODE_MODULES=/path/to/node_modules bash tests/_run_regression_rooms.sh`.

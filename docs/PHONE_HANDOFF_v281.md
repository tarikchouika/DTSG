**إلى:** مساعدي المسؤول عن خادم الهاتف
**من:** فريق المنصة (جهة الويب/الخادم الخلفي)
**التاريخ:** 2026-10-03 · **الإصدار:** v2.81.1 (تسليم v2.81.0 مُحدَّثاً)
**المرجع:** توجيه المالك — مستندا «ربط MediaMTX API بالباكأند» و«بناء APK بـ Capacitor»

## 0. ملخص ما جرى (ماذا تغيّر ولماذا)

متصفحات الهواتف كلها لا توفّر واجهة مشاركة الشاشة (`getDisplayMedia`) — قيد
منصّي لا يمكن تجاوزه داخل المتصفح. البديل المعتمد: اللاعب يبث شاشة هاتفه من
**تطبيق بث RTMP مجاني** (مثل Larix Screencer) إلى مرحّل **MediaMTX** على خادم
الهاتف، والأدمن يشاهده في لوحة التحكيم كما يشاهد بث المتصفح تماماً.

> ✅ **[v2.81.1] تحديث الحالة — المرحّل صار مُثبَّتاً فعلاً، لا خطوة قادمة:**
> **MediaMTX v1.21.1** مثبَّت في `/root/mediamtx/mediamtx` تحت pm2 باسم
> `mediamtx`، وإعداده `/root/DTSG/mediamtx.yml`، وواجهة استعلامه تردّ على
> `127.0.0.1:9997`. فالخطوات 2 و3 أدناه **مُنفَّذةٌ بالفعل** وموثّقة هنا بأوامر
> التحقّق لا بخطوات تُنفَّذ. **ومتبقٍّ واحد:** اختيار وسيلة نشر 1935 العامة
> (§4) وضبط `MEDIAMTX_RTMP_URL` — **قرار المالك وحده**. ولا يعني ذلك أن نشر
> شاشة الهاتف يعمل الآن: **لا يعمل بعد**، لأن لا عنوان عام بعد (§4).

ومعه جاءت **مراقبة حالة البث** (هل اللاعب يبث فعلاً أم انقطع؟) ربطاً
لـMediaMTX API بالباكأند بثلاثة قيود صارمة: استعلام Loopback حصراً (صفر
باندويث عبر النفق)، عند الطلب حصراً (لا حلقات خلفية)، وعزل تام (توقف المرحّل
لا يمسّ الخادم ولا القاعدة).

> 🔒 **[v2.81.1] وأُغلق بند المصادقة المفتوح الذي حذّر منه v2.81:** كان كل من
> يصل إلى منفذ RTMP يستطيع النشر في مسار أي غرفة، والباكأند يستنتج «هذا اللاعب
> يبث» من مجرّد جاهزية المسار — ومعرّفا الغرفة واللاعب أرقام صغيرة متسلسلة،
> ورقم الغرفة ظاهر في لوحة الأدمن ⇒ **انتحال بثّ الخصم أمام الأدمن في قرار
> يُفرج عن المال**. **الحل: رمز داخل المسار** مشتقّ من سرّ الخادم
> `ARB_STREAM_SECRET`، والباكأند يعيد اشتقاقه للمقارنة فلا يُصدَّق مسار بلا رمز.
> **التفصيل الكامل والقواعد في §4 بند 2** — اقرأه قبل الاختبار الميداني.

**جهة المنصة (أنجزت وتُدفع مع هذا الإصدار):** وحدة المراقبة `server-mediamtx.js`
+ نقطة النهاية `GET /api/matches/:roomId/stream-status` (أدمن حصراً) + جدول
`arb_stream_events` + تنبيهات SSE للأدمن بعد انقطاع >30ث + بطاقة إرشاد الهاتف
في صفحة التحكيم المباشر (عنوان RTMP خاص بكل لاعب مع زر نسخ، مترجمة ×4) + سطر
حالة المرحّل في المشاهدة المزدوجة + **رمز المسار المُشتقّ بـHMAC داخل المسار**
(§4) + سير عمل GitHub Actions لبناء APK تلقائياً.

**جهتكم (خادم الهاتف):** **الخطوة 4 وحدها** (§4) — كل ما عداها مُنفَّذ وموثّق هنا.

## 2. تثبيت MediaMTX وتشغيله تحت pm2 + تحديث إعداده

> ✅ **[v2.81.1] هذه الخطوة نُفِّذت على هذا المضيف** — لا تُعيدوها إلا على جهاز
> جديد بلا مرحّل. الأوامر أدناه هي التي نُفِّذت حرفياً، **وأهمّ سطر فيها ليس
> `pm2 start` بل تمرير الإعداد كوسيط صريح** (انظر 2.3).

هذه **أول خطوة فعلية على الجهاز**. الثنائي يُجلب من **إصدار مثبَّت رقمياً**
(`v1.21.1`) لا من `latest` — رابط `latest` يجعل ما يُبنى غير قابل للتكرار،
ولا بد من مطابقة `checksums.sha256` قبل التشغيل. المضيف `aarch64` ⇒ حزمة
`linux_arm64`.

**2.1 تحميل الثنائي والتحقق من بصمته**

```bash
VER=v1.21.1
ARCH=linux_arm64                 # على x86_64 تكون linux_amd64
mkdir -p /root/mediamtx && cd /root/mediamtx
wget -q "https://github.com/bluenviron/mediamtx/releases/download/${VER}/mediamtx_${VER}_${ARCH}.tar.gz"
wget -q "https://github.com/bluenviron/mediamtx/releases/download/${VER}/checksums.sha256"
tar -xzf "mediamtx_${VER}_${ARCH}.tar.gz"
sha256sum -c --ignore-missing checksums.sha256     # يجب: mediamtx_...tar.gz: OK
./mediamtx --version                               # يجب: v1.21.1
```

**2.2 تفعيل واجهة الاستعلام + حصر كل المستمعين على Loopback [v2.81.1]** — ملف
`mediamtx.yml` المرفق بالمستودع مُصحَّح في v2.81 (انظر الخطوة 4 بند 2)،
و**[v2.81.1] يثبّت كل مستمع على `127.0.0.1`** لأن افتراض MediaMTX هو الربط على
**كل الواجهات** (فكان أي جهاز على شبكة الهاتف يصل مباشرةً إلى
1935/8554/8888/8889):

```yaml
api: yes
apiAddress: 127.0.0.1:9997
rtmpAddress: 127.0.0.1:1935      # الاستثناء الوحيد: خيار الراوتر — انظر §4
rtspAddress: 127.0.0.1:8554
hlsAddress: 127.0.0.1:8888
webrtcAddress: 127.0.0.1:8889
```

```bash
cp /root/DTSG/mediamtx.yml /root/mediamtx/mediamtx.yml   # استبدلوا نسختكم بالملف المرفق
```

> الأرشيف نفسه يحوي ملف `mediamtx.yml` **بإعداداته الافتراضية من
> التوزيعة** — لا تتركوه مكان ملف المستودع: لا كتلة `~^dtsg` فيه، فلا
> يُقبل نشر إلا بالمسارات الافتراضية. التحقّق بعد النسخ:
> `grep -c dtsg /root/mediamtx/mediamtx.yml` ⇒ عدد أكبر من صفر.
>
> **⚠ [v2.81.1] تحقّق إضافي إلزامي بعد النسخ — الحصر على Loopback:**
> `grep -E '^(rtmp|rtsp|hls|webrtc|api)Address' /root/mediamtx/mediamtx.yml`
> ⇒ **كل سطر يجب أن يبدأ بـ`127.0.0.1:`**، و`rtmpAddress: 127.0.0.1:1935`
> تحديداً. فإن رأيت سطراً على `:1935` بلا `127.0.0.1` فهذا إما خطأ نسخ وإما
> أن أحدهم فتح 1935 على الشبكة — وكلاهما يُرجَع (§4 الخيار **ب** هو الوحيد الذي
> يبرّره).

> **ممنوع** فتح المنفذ 9997 للخارج أو تمريره عبر أي نفق — استعلاماته من
> الباكأند على نفس الجهاز حصراً (عقد المستند: صفر باندويث عبر النفق).
> **ومتحقَّق منه عددياً [v2.81.1]:** نفق `dmgames-local` له قاعدة ingress واحدة
> فقط (catch-all إلى `http://localhost:3000`) و**لا قاعدة توجّه 9997 ولا 8889
> ولا 1935** — فحص عبر Cloudflare API، فواجهة المراقبة غير قابلة للوصول علنياً.

**2.3 التشغيل — تحت pm2 حصراً، لا systemd ولا `nohup`** · ✅ **[v2.81.1] نُفِّذ**

```bash
cd /root/mediamtx
pm2 delete mediamtx >/dev/null 2>&1 || true     # إن وُجدت نسخة قديمة
pm2 start /root/mediamtx/mediamtx --name mediamtx --cwd /root/mediamtx -- /root/DTSG/mediamtx.yml
pm2 save                                       # ليعود بعد إعادة تشغيل الجهاز
sleep 2

# ————— التحقّق (وهذا هو المرجع، لا خطوات التثبيت) —————
pm2 status | grep mediamtx                          # المطلوب: online
pm2 describe mediamtx | grep 'script args'           # المطلوب: /root/DTSG/mediamtx.yml   ← لا فارغ!
curl -s http://127.0.0.1:9997/v3/paths/list
# المطلوب: {"itemCount":0,...} أو قائمة المسارات — أي جواب JSON يعني الواجهة حيّة
```

> **⚠⚠ الحادثة الصامتة — لماذا صار الوسيط `… -- /root/DTSG/mediamtx.yml`
> إلزامي في السطر أعلاه [v2.81.1]:** **أول تشغيل** تحت pm2 **تمّ بلا مسار
> إعداد** ⇒ بحث MediaMTX عن `mediamtx.yml` بجوار الثنائي فلم يجده، فاستقال على
> **إعداداته الافتراضية بصمت — بلا تحذير وبلا خطأ واحد**، وpm2 كان يُظهر
> `online` كأن كل شيء سليم. والنتيجة كانت: **كل المنافذ مربوطة على كل
> الواجهات** (1935/8554/8888/8889/9997 مكشوفة على شبكة الهاتف) و**بلا كتلة
> `~^dtsg` أصلاً** (لا قيود مسارات إطلاقاً).
> ⇒ **القاعدة: `online` دليل تشغيلٍ لا دليل إعداد — سطر `script args` في التحقّق
> ليس زينة، بل هو الفحص الوحيد الذي كان سيكشفها.**، ولا تعوّدوا تشغيل
> `./mediamtx` يدوياً أبداً (بلا مشرف ⇒ لا يعود بعد الريبوت).

**بنِدان إلزاميان، لكلٍّ سبب مُتحقَّق منه على هذا المضيف:**

1. **لا systemd إطلاقاً.** المضيف لا يدير العمليات بـsystemd (`systemctl
   is-system-running` ⇒ `offline`، و`/proc/1` ليس systemd) ⇒ وحدة
   `mediamtx.service` **لن تعمل ولن تنطلق بعد إعادة التشغيل**، والعملية التي
   تُشغَّل بلا مشرف لا يعود pm2 يعرفها. pm2 هو المشرف الوحيد الموجود فعلاً
   (`casino-server` · `cloudflared-tunnel` · `dtsg-voucher-bot` …).
2. **لا `nohup … &` ولا `&` عارية.** عملية لا يشرف عليها pm2 **لا تعود بعد
   إعادة تشغيل الجهاز** ⇒ تختفي أسطر حالة المرحّل من لوحة الأدمن بعد أول
   ريبوت وتظنّ المنصة أن المرحّل «ميت» وهو مُثبَّت على القرص.

**2.4 إعادة تشغيل عملية المنصة — الطريقة الوحيدة المعتمدة**

كل تعديل في `.env.local` يتم عبر:

```bash
bash scripts/phone-env-restart.sh
```

**وليس** `pm2 restart --update-env` من صدفة ناقصة (قاعدة AGENTS #9 — حادثة
2026-09-22: مُسحت كل متغيرات الدفع والبوتات ثم حُفظت بـ`pm2 save`).
`phone-env-restart.sh` يقرأ `.env.local` ← يعيد التشغيل ← يتحقق من المفاتيح
(منها مفاتيح بوت المالية) ← `pm2 save`. لإعادة تشغيل **المرحّل نفسه** بعد
تعديل `mediamtx.yml`: `pm2 restart mediamtx && pm2 save` — المرحّل ليس عملية
المنصة فلا يدخل به `phone-env-restart.sh`.

## 3. متغيرات البيئة (.env.local)

**أولاً — تصحيح ادّعاء غير صحيح [v2.81].** كانت هذه الشريحة تقول إن
`MEDIAMTX_WHIP_URL` و`ARB_STUN_URLS` «موجودان منذ v2.78». الفحص على هذا
الجهاز (2026-10-03) يومها يعطي:

```bash
grep -c '^MEDIAMTX' .env.local        # => 0
grep -c '^ARB_STUN'  .env.local       # => 0
```

**(v2.81.1) وما تغيّر في الملف منذ ذلك الفحص:** أضيف **`ARB_STREAM_SECRET`** و
**`MEDIAMTX_API_URL`** (الأخير افتراضه `127.0.0.1:9997`)، وبقي
`MEDIAMTX_WHIP_URL` و`MEDIAMTX_RTMP_URL` **متعمَّداً غير مضبوطين** ⇒
**احتياطي WHIP من v2.75 ما زال غير مفعّل**، وادّعاء «موجود منذ v2.78» كان خاصاً
بغير هذا الجهاز. **وهذا ليس عطلاً:** البث P2P (WebRTC) هو المسار الأساسي ويعمل
بلا متغيّر MediaMTX إطلاقاً؛ والمرحّل المنشور تحت pm2 يخدم **المراقبة** (§8 من
`docs/ARBITRATION_SETUP.md`) لا مسار الفيديو. وإن توقّف المرحّل بدت لوحة الأدمن
شريحة **«⚫ المرحّل لا يرد»** ([v2.81] شريحة جديدة تلتقطها `arb-admin.js` من
`available:false`) بدل أن يبتلع الصمت وتبدو «المرحّل مطفي» و«اللاعب ساكت»
شيئاً واحداً.

**ثانياً — متغيّر **جديد** [v2.81.1] لا بدّ منه قبل أي نشر:**

```bash
# سرّ اشتقاق رمز المسار — مطلوب، ومولَّد مرة واحدة ولا يُدوَّر إلا بصيانة:
ARB_STREAM_SECRET=$(openssl rand -hex 32)      # أو أي سلسلة عشوائية طويلة
```

**قواعده الإلزامية:** (1) في `.env.local` **وحده** — **لا في المستودع ولا في
`mediamtx.yml`** (كلاهما معلن على GitHub)؛ (2) **لا يُطبع في السجل ولا يُكتب في
`arb_stream_events`**؛ (3) غيابه لا يُسقط المنصة (يُولَّد سرّ عشوائي لهذا التشغيل
مع **تحذير إقلاع صريح** في سجل الخادم) **لكنه يُبطل كل مسارات النشر عند كل
إعادة تشغيل**؛ (4) **تدويره يُبطل كل المسارات الحيّة فوراً** ⇒ صيانة مقصودة
فقط، متبوعة بإعادة نَسخ العناوين من صفحة التحكيم.

**ثالثاً — ما تبقى (اختيارية أو معلّقة):**

```bash
ARB_STUN_URLS=stun:stun.l.google.com:19302,stun:stun1.l.google.com:19302
MEDIAMTX_API_URL=http://127.0.0.1:9997              # افتراضي — كتابته اختيارية
MEDIAMTX_RTMP_URL=rtmp://<العنوان-العام>:1935       # من الخطوة 4 — إلزامي لمشاركة شاشة الهاتف
```

ثم `bash scripts/phone-env-restart.sh` (الطريقة المعتمدة حصراً — الخطوة 2.4).

- `MEDIAMTX_WHIP_URL` (احتياطي v2.75) اتركوه **غائباً**: كتابة العنوان تعطي
  اللاعبين واجهةً توهم بوجود احتياطي غير مفعّل. إن رغبتم في تفعيل WHIP ⇒
  `MEDIAMTX_WHIP_URL=http://127.0.0.1:8889`.
- بدون `MEDIAMTX_RTMP_URL`: المنصة تعمل طبيعياً لكن **بطاقة الهاتف لا تظهر
  للاعبين** (سلوك مقصود — لا عنوان لا ميزة) ⇒ **وهذا حالنا اليوم بالضبط:**
  المرحّل مُثبَّت والمراقبة حيّة، **ولا يُنشر بثّ هاتف بعد**.
- `MEDIAMTX_API_URL` يجب أن يبقى عنواناً محلياً؛ ضبطه بعنوان عام يُطبع تحذير
  في سجل الخادم (انحراف عن العقد) والنظام يستمر بالعمل رغم ذلك.

## 4. نشر منفذ RTMP (1935) للخارج — قرار معماري لكم

هذه **الخطوة البنيوية الجديدة الوحيدة على مستوى الشبكة**، و**الخطوة الوحيدة
المتبقّية من هذا التسليم**: لاعبو الهواتف يبثون من خارج شبكة الخادم، فلا بد من
عنوان عام يصل إلى منفذ RTMP 1935 على جهازكم. المرحّل الآن **مثبَّت ويستمع
محلياً على `127.0.0.1:1935`** (لا على كل الواجهات — [v2.81.1])، ويَلزمكم تمريره
فقط. والخيارات مرتّبة **أمنياً لا سهولةً**:

| الخيار | المتطلبات | الخطوات المختصرة | الأثر الأمني [v2.81.1] |
|---|---|---|---|
| **أ) playit.gg (نفق TCP مجاني — موصى به)** | حساب مجاني + tunnel على الجهاز | أنشئوا tunnel نوع TCP إلى `127.0.0.1:1935` ⇒ يعطيكم عنواناً ثابتاً `rtmp://<نطاق>.gg:<منفذ>` — ضعوه في `MEDIAMTX_RTMP_URL` | ✅ **الأقوى**: 1935 يبقى محشوراً على Loopback، والعالم كله يصل عبر قناة واحدة يمكن إيقافها بنقرة |
| **ج) VPS صغير كمرحّل أمامي** | VPS بسيط (أرخص فئة) | على الـVPS: `socat TCP-LISTEN:1935,fork,reuseaddr TCP:<عنوان-خادم-الهاتف>:1935 &` (عنوان الهاتف: نفق TCP أو IP العام) | ✅ قوي كذلك إن كان العنوان نفقاً؛ **فإن كان IP عاماً فهو كخيار ب** لأن 1935 يبقى مفتوحاً للعالم |
| **ب) توجيه منفذ في الراوتر + DDNS** | IP عام من المزود + تحكم بالراوتر | forward خارجي 1935 → `<ip-الجهاز>:1935` + اسم DDNS إن كان IP متغيراً، وفي `mediamtx.yml` غيّر `rtmpAddress` إلى `:1935` (بلا `127.0.0.1`) | ⚠️ **الأضعف**: يفرض فكّ الحصر ⇒ 1935 مكشوف على شبكة الهاتف وعلى الإنترنت مباشرةً، ومَن يعرف عنوانك فقط يستطيع المحاولة. ومع أن رمز المسار (بند 2 أدناه) هو المصادقة، **فهذا الخيار وحده يوسّع سطح الهجوم بدل أن يضيّقه** |

**⚠ القرار المتبقّي للمالك وحده** — لا يُنفَّذ أيٌّ من الثلاثة تلقائياً، وأقوى
الثلاثة (أ) هو الموصى به. وأيّها اختارتم، **[v2.81.1] الخيار ب يستلزم تحرير سطر
في `mediamtx.yml`** (`rtmpAddress: :1935`) ثم `pm2 restart mediamtx && pm2 save`
— لا تفعلوها إن لم تختاروه صراحةً.

**تنبيهات أمنية إلزامية:**

1. **1935 فقط** هو المنشور — لا تُنشروا 8889 (WHIP/WHEP) للعامة عبر هذا المسار
   ولا 9997 إطلاقاً (مشاهدة الأدمن تعمل من نفقها القائم — راجع §5.1.1 من
   `docs/ARBITRATION_SETUP.md`؛ ومُتحقَّق عددياً أن نفق `dmgames-local` لا يوجّه
   أياً منها).

2. **شكل المسار في `mediamtx.yml` — تعبير نمطي لا اسم حرفي، ومُرمَّز [v2.81.1].**
   المفتاح `~^dtsg:` (تعبير نمطي يطابق كل مسار يبدأ بـ`dtsg`) يغطي صيغتي
   النشر معاً، **وهما الآن الصيغتان المُرمَّزتان**:

   | الصيغة المعتمدة | من ينشرها | تغطية `~^dtsg` |
   |---|---|---|
   | `dtsg/<roomId>/<userId>_<token>` | تطبيق RTMP على الهاتف (Larix) | ✅ |
   | `dtsg-<roomId>-<userId>_<token>` | **WHIP الفعلي** الصادر من `js/core/arb-client.js` (`/whip/dtsg-` + `roomId` + `-` + `userId` + الرمز) | ✅ |
   | ~~`dtsg/<roomId>/<userId>`~~ (بلا رمز) | — | **مُهمَل عمداً** (§5.2) |

   > **سبب تغيير الاسم [v2.81]:** الاسم القديم `dtsg/` كان **مرفوضاً** من
   > `IsValidPathName` (اسم المسار لا ينتهي بشرطة مائلة) ⇒ لم يكن MediaMTX
   > يُقلع أصلاً على أي إصدار v1.x؛ و`fallback: present` كان حقل إعادة توجيه
   > (redirect) لا يقبل إلا مساراً أو عنوان RTSP ⇒ حُذف السطر، والمقصود
   > («يقبل هذا المسار من ينشر إليه») هو `source: publisher` وحدها.
   > ولا تكتبوا `~^dtsg/` أبداً — الشرطة الذيلة تُخرج المفتاح من دائرة
   > التعابيرية فيعود الرفض نفسه.

3. **✅ [v2.81.1] بند مصادقة النشر — كان مفتوحاً في v2.81، وهو الآن مُغلق. (التفصيل
   الكامل في `docs/ARBITRATION_SETUP.md` §5.2.)

   **كان الخطر:** كتلة `~^dtsg` بلا أي مصادقة نشر (`publishUser`/`publishPass`
   مهجوران)، وكل من يصل إلى 1935 عبر النفق العام **يستطيع النشر في مسار أي
   غرفة**؛ ولا يصحّ الاعتماد على ظاهر المسار بوصفه سرّية — `roomId` و`userId`
   أرقام صغيرة ورقم الغرفة ظاهر في لوحة الأدمن ⇒ التخمين عمليّ. والأثر **ماليّ
   غير مباشر**: `stream-status` كانت تستنتج «هذا اللاعب بعينه يبث» من مجرّد
   جاهزية المسار، فنشرٌ من خارج الهاتف **يوهم الأدمن بأن لاعباً يبث وهو صامت**
   — والحسم قرار سوبر-أدمن يُفرج عن الإيداعات.

   **ما نُفِّذ — رمز داخل المسار:**
   `token = أول 16 خانة hex من HMAC-SHA256(ARB_STREAM_SECRET, "<roomId>:<userId>")`
   — يولّده `server-mediamtx.js` ويضعه في المسار، ويُسلَّم **للاعب الجالس في
   غرفته وحده** (في `start-stream` و`/api/matches/mine`)، ويعيد المراقب
   اشتقاقه من السرّ نفسه للمقارنة ⇒ **مسار بلا رمز لا يُقرأ دليلاً على أي
   شيء**. والدليل مادّي: نشر `ffmpeg` حقيقي على المسار المجرّد **لم** يُبلَّغ
   أنه متصل، وعلى المسار المُرمَّز **قُرئ** `online` ببايتات ومدة صحيحة.
   **وMediaMTX نفسه يبقى بلا مصادقة نشر** ⇒ الرمز هو طبقة المصادقة الوحيدة،
   ومقبول لأن الجاهزية لم تعد دليلاً بلا رمز.

   **ما يبقى من البند القديم بحرفه:** لا تفتحوا 1935 إلا عند الحاجة، وأوقفوا
   النفق فور انتهاء الاختبار الميداني، ولا تنشروا 9997/8889 أبداً.

4. **قاعدة التوزيع [v2.81.1]:** كل لاعب **ينسخ مساره الخاص من البطاقة** ولا
   يبنيه بنفسه ولا يحذف اللاحقة ولا يقصّ العنوان قبل `_` — فإن نشر على مسار
   غير مُرمَّز أو برمز خطأ ⇒ **لن يظهر عند الأدمن**، ولو بدا ذلك عطلاً فهو
   السلوك الصحيح.

## 5. إعادة تشغيل الخادم والفحوص بعد التشغيل


> **بعد كل ريبوت للجهاز:** `pm2 save` (في الخطوة 2.3) هو ما يُعيد تشغيل
> المرحّل تلقائياً — تحقّقوا منه بسطر `pm2 status` أعلاه قبل أي فحص آخر.
> طلبات `stream-status` كلها تنتهي الآن بلا تعليق حتى لو مات المرحّل أثناء
> قراءته ([v2.81] حارس زمني في `server-mediamtx.js` يضمن استدعاء نداء راجع
> واحداً على كل طريق).

## 6. اختبار ميداني شامل (10 دقائق بحسابين على هاتفين)

1. أنشئوا غرفة تحكيم من المنصة (تبويب «📺 غرفة تحكيم مباشر») بحسابين وابدؤوا
   الجولة بعد إيداع الرهان.
2. من هاتف اللاعب الأول: افتحوا **التحكيم المباشر** (`#arb`) — تظهر بطاقة
   «📱 مشاركة شاشة الهاتف» وعنوان بثّه الخاص **بصيغته الكاملة بما فيه اللاحقة
   `_` والرمز** وزر 📋 نسخ. (لا تظهر البطاقة إلا على متصفح هاتف فعلاً وعندما
   `MEDIAMTX_RTMP_URL` مضبوط — أي بعد اختيار وسيلة النقل في §4.)
3. على الهاتف: ثبّتوا **Larix Screencer** (مجاني) → إعدادات البث → RTMP →
   الصقوا العنوان **كما هو بلا قصّ** → فعّلوا «بث الشاشة / Screen capture» →
   ابدأوا. **[v2.81.1] إن نشرتَ على مسار بلا رمز أو برمز ناقص فلن يظهر عند
   الأدمن أبداً — وهذا هو السلوك الصحيح لا عطل (§4 بند 2).**
4. من لوحة الأدمن افتحوا الجلسة (المشاهدة المزدوجة): تحت فيديو اللاعب يظهر
   **«🟠 المرحّل مباشر · <حجم> · <مدة>»** يتحدث كل 10ث.
5. أوقفوا البث من Larix وانتظروا ~35ث واللوحة مفتوحة: **🚨 toast انقطاع**
   + صف جديد في `arb_stream_events` (kind=offline). أعدوا البث: **🟠 عاد**
   (kind=recovered).
6. كرروا من هاتف اللاعب الثاني ⇒ المشاهدة المزدوجة مكتملة والسطران أخضران.

## 8. المحظورات والتراجع الآمن

- **لا تعدّلوا** ملفات المال (`server-financials.js`، عقد التسوية) ولا
  `server-mediamtx.js` — المراقبة بلا أي قرار مالي (تنبيه حصراً، الحسم للأدمن).
- **لا تضبطوا** `MEDIAMTX_API_URL` بعنوان عام ولا تنشروا 9997/8889 عبر نفق
  RTMP الجديد.
- **[v2.81.1] لا تكتبوا `ARB_STREAM_SECRET` في `mediamtx.yml` ولا في المستودع
  ولا في أي ملف يُرفع** — في `.env.local` وحده. **ولا «تنقوه» إلى
  `/root/.secrets`:** الخادم يقرؤه من البيئة وقت الإقلاع، ونقله يجعله غير
  مقروء للخادم. **ولا تدوروه** إلا في صيانة مقصودة: التدوير يُبطل كل المسارات
  الحيّة ويقرأ كل اللاعبين «غير متصل» حتى يعيدوا النسخ من البطاقة.
- **[v2.81.1] لا تفتحوا `rtmpAddress` على `:1935`** إلا إذا اختارتم صراحةً
  الخيار **ب** في §4؛ فكل سطر آخر يجب أن يبقى على `127.0.0.1`.
- **لا تشغّلوا** MediaMTX بملف إعداد قديم بلا `api: yes` — حينها تختفي أسطر
  حالة المرحّل من لوحة الأدمن (الغياب مقصود بلا كسر) ويفقد الأدمن رؤية
  الانقطاع عبر المرحّل فقط؛ بث P2P من الحاسوب لا يتأثر إطلاقاً.
- **التراجع الكامل:** `git checkout 56b872a` + `cp /root/DTSG/mediamtx.yml`
  قبل التعديل (أو حذف سطري `api:` و`apiAddress:` من نسخة `mediamtx.yml`
  لديك) + حذف `MEDIAMTX_RTMP_URL` من `.env.local` ثم
  `bash scripts/phone-env-restart.sh` — كل مكونات v2.81 اختيارية التفعيل
  ورسوبها تراجع نظيف بلا أثر على المكتسبات.
- **[v2.81·تصحيح مرجع خاطئ] `56b872a` لا `v2.80.0`:** كان السطر السابق يطلب
  `git checkout v2.80.0`، والمستودع **بلا أي وسم** (`git tag | wc -l` ⇒ `0`)
  ⇒ الأمر يفشل بـ`pathspec 'v2.80.0' did not match`. المرجع الصحيح **معرّف
  التزامن** لا وسم:

  ```bash
  git tag | wc -l            # => 0  (لا وسمات في هذا المستودع)
  git cat-file -t 56b872a    # => commit
  git log -1 --oneline 56b872a
  # [تصحيح ما بعد v2.80.0] عزل بيئة الاختبار كان ناقصاً ... (2026-10-03)
  git checkout 56b872a       # آخر التزامن قبل v2.81.0 ⇒ تراجع نظيف ومُتحقَّق منه
  git checkout main          # بعد الانتهاء: ارجع إلى الفرع
  ```

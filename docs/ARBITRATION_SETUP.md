## 1. مخطط البنية (Architecture Flow)

```
┌──────────────────────── DSTSG Live Arbitration ────────────────────────┐
│                                                                        │
│  [اللاعب A] ──getDisplayMedia──► RTCPeerConnection ──┐                 │
│       │                                   ▲           │ فيديو P2P      │
│       │ offer/answer/ICE                   │           ▼ مباشر         │
│       │ (POST /api/arb/signal)             │    [لوحة الأدمن]          │
│       ▼                                    │     فيديو A │ فيديو B     │
│  ┌─────────────────────────────────────┐   │      (جنباً إلى جنب)      │
│  │  خادم الإشارات (Signaling فقط!)      │◄──┘           │             │
│  │  server-arbitration.js               │               │ أزرار:      │
│  │  • يرحّل العروض/الأجوبة/ICE           │◄──────────────┘ فوز A/B ·    │
│  │  • جلسات + توكنات (SQLite)           │     نزاع · إلغاء/استرداد     │
│  │  • نبض + منظّف انقطاع (15ث)          │               │             │
│  └──────────────┬───────────────────────┘               ▼             │
│                 │ ناقل SSE الحي القائم (/api/live)      │             │
│  [اللاعب B] ────┘  (arb:signal / arb:session /          │             │
│                     arb:resolved)                        │             │
│                                                          ▼             │
│              الحسم ⇒ نواة التسوية المعتمدة نفسها (arbResolve/arbCancel) │
│              ⇒ إفراج عن الإيداعات: الرابح +الجرة − 5% · أو استرداد كامل │
│                                                                        │
│  بديل P2P تعذّر ⇒ نشر WHIP إلى MediaMTX محلي ⇒ الأدمن يشاهد عبر WHEP   │
└────────────────────────────────────────────────────────────────────────┘
```

> **[v2.81] السطر الأخير من الرسم — بديلٌ غير مفعَّل على هذا المضيف.**
> `MEDIAMTX_WHIP_URL` غير موجودة في `.env.local` ولا مرحّل مثبَّت ⇒ **الحالة
> الفعلية اليوم: P2P حصراً** (وهو المسار الأساسي، لا بديلاً). التفاصيل والجدوى
> في §5.

**قررارات معمارية (لماذا هكذا؟):**

| القرار | السبب |
|---|---|
| **WebRTC P2P** للفيديو | الفيديو لا يمر بالخادم إطلاقاً: صفر ترميز وصفر باندويث على معالج الهاتف (Cat S62: 4GB RAM) وعبر نفق Cloudflare المجاني. |
| **الإشارات عبر POST + ناقل SSE القائم** بدل WebSocket | لا مكتبة جديدة (`ws`) ولا منفذ إضافي عبر النفق؛ ناقل `/api/live` مُختبَر في الإنتاج منذ v2.43 ويعبر Cloudflare Tunnels أصلاً. إشارات WebRTC JSON صغيرة — أجزاء الثانية كافية تماماً للمصافحة. |
| **الحسم عبر نواة التسوية نفسها** (`settleSeatCore`) | لا مسار مال جديد قط (قاعدة AGENTS #12): نفس عقد المال v2.71+ — الرابح يستلم الجرة − 5%، سجل معاملات كامل (win/refund)، تذاكر الجولة، و`room.settled` يمنع الازدواج. الفارق الوحيد: التفويض بصلاحية الأدمن بدل عضوية الغرفة. |
| **توكن لكل لاعب في الجلسة** | الإشارة/النبض تطلبه حصراً؛ الحسم/الإلغاء يتطلبان صلاحية أدمن (role) — لا يستطيع لاعب حسم مباراته. |
| **«المباراة» = غرفة اللعب** | رهاناتها مودَعة في escrow عند البدء — وهي وحدة التحكيم الطبيعية على المنصة. |

## 3. نقاط النهاية (API)

| المسار | الدور | التصريح |
|---|---|---|
| `POST /api/matches/:roomId/start-stream` | فتح/جلب جلسة التحكيم للجولة الجارية + توكن البث (idempotent) | لاعب نشط في الغرفة |
| `GET /api/matches/mine` | **[v2.76]** جلستي: غرفة المستخدم الجارية + جلسة التحكيم المرتبطة (بلا توكنات) | مستخدم مسجل الدخول |
| `GET /api/matches` | قائمة الجلسات النشطة | أدمن/سوبر |
| `POST /api/matches/:roomId/resolve` | الحسم: `{status:'completed', winner_id}` أو `{status:'disputed'}` | **أدمن/سوبر حصراً** |
| `POST /api/matches/:roomId/cancel` | إلغاء + استرداد كامل للرهانات | **أدمن/سوبر حصراً** |
| `POST /api/arb/signal` | ترحيل `offer/answer/ice/rewatch/bye` (توكن اللاعب إلزامي) | أطراف الجلسة + الأدمن |
| `POST /api/arb/heartbeat` | نبض البث (state: idle/connecting/live/relay/failed) | لاعب بتوكنه |
| `GET /api/matches/:roomId/stream-status` | **[v2.81]** حالة بث المرحّل لطرفي المباراة (أ + ب) من MediaMTX API محلياً — `available · player_a_status{online,ready,bytes_rx,stream_duration,path,offline_since,alert} · player_b_status · arbitration_ready` + تنبيه الانقطاع > 30ث (صف `arb_stream_events` + حدث SSE `arb:stream`) | **أدمن/سوبر حصراً** |

أحداث SSE على `/api/live`: `arb:signal` (الإشارات) · `arb:session` (تحديث حالة الجلسة/انقطاع) · `arb:resolved` (حسم نهائي) · `arb:stream` **[v2.81]** (انقطاع/عودة بث المرحّل بعد تجاوز مهلة المراقبة).

## 4. التشغيل خطوة بخطوة (سيناريو كامل)

> **[v2.76]** السيناريو نفسه يعمل من **صفحة التحكيم المخصّصة** (‪#arb‬ — عنصر تنقل «التحكيم المباشر»): اللاعب من بطاقة «جلستي الحالية» فيها، والأدمن من مركز التحكيم داخلها (إحصاءات + جلسات + مشاهدة مزدوجة + حسم). مودال الغرفة وتبويب لوحة الإدارة يبقيان يعملان كما هما.

1. **لاعبان** يبدآن جولة وجه لوجه (غرفة بأي لعبة، برهان) — الرهانات تُقتطع في escrow عند البدء كالمعتاد.
2. أحد اللاعبين يفتح **مودال الغرفة** ⇒ يظهر صندوق «📺 بث التحكيم المباشر» ⇒ ينقر **مشاركة الشاشة / بدء البث** ⇒ يسمح للمتصفح بمشاركة الشاشة.
   - المؤشر: 🟡 يتم الاتصال… ⇒ 🟢 **مباشر — الأدمن يشاهد** (أو 🟠 عبر المرحّل عند سقوط P2P).
   - يمكن للاعبه الآخر مشاركة شاشته كذلك — الأدمن يشاهد الاثنين معاً.
3. **الأدمن** (أو السوبر) يفتح لوحة التحكم ⇒ تبويب **📺 التحكيم** ⇒ تظهر بطاقة الجلسة (اللاعبان + حالة بث كل منهما) ⇒ ينقرها ⇒ **المشاهدة المزدوجة**.
   - انقطاع بث أي لاععب > 15ث ⇒ ⚠️ تنبيه آلي في اللوحة (منظّف خادمي كل 5ث).
4. عند حسم النتيجة: **✅ تأكيد فوز اللاعب الأول/الثاني** ⇒ إفراج خادمي فوري عن الإيداعات (الرابح +الجرة − 5%، مع دفعة محفظة فورية للطرفين).
   - **⚖️ نزاع** أو **❌ إلغاء/إرجاع الأموال** ⇒ استرداد كامل للجميع (صفوف refund في السجل).
5. الجلسة تُقفل (لا إشارات ولا حسم مزدوج) وتُحفظ في `arb_sessions` للتدقيق.

## 5. الخيار البديل: MediaMTX (RTMP/WHIP عند تعذر P2P)

شبكات بعض اللاعبين تحجب P2P (UDP محجوب/NAT صارم) — عندها يحاول عميل اللاعب نشر شاشته عبر **WHIP** إلى MediaMTX يعمل على نفس الهاتف، والأدمن يشاهده عبر **WHEP** (وسم 🟠 عبر المرحّل).

**حالة هذا المضيف (2026-10-03): MediaMTX غير مثبَّت أصلاً** — لا ثنائي على
القرص ولا مجلد `~/mediamtx`، والمنافذ `9997/1935/8889` ترفض الاتصال. فـ
«التركيب» أدناه خطوة **اختيارية تُنفَّذ عند الحاجة فقط**؛ المسار الأساسي (P2P)
يعمل بلا مرحّل إطلاقاً. الإجراء الكامل المُثبَّت رقمياً والمُشَرَّح خطوة بخطوة
(تحميل إصدار pinned + بصمة `checksums.sha256` + تشغيل تحت **pm2**) في
`docs/PHONE_HANDOFF_v281.md` §2.

**التركيب (مرة واحدة) — إن أردتم تفعيل المرحّل:**
```bash
VER=v1.21.1                      # إصدار مثبَّت رقمياً — لا تستعملوا رابط latest
ARCH=linux_arm64                 # على x86_64: linux_amd64
mkdir -p /root/mediamtx && cd /root/mediamtx
wget -q "https://github.com/bluenviron/mediamtx/releases/download/${VER}/mediamtx_${VER}_${ARCH}.tar.gz"
wget -q "https://github.com/bluenviron/mediamtx/releases/download/${VER}/checksums.sha256"
tar -xzf "mediamtx_${VER}_${ARCH}.tar.gz"
sha256sum -c --ignore-missing checksums.sha256
cp /root/DTSG/mediamtx.yml ./mediamtx.yml # الإعداد المرفق بالمستودع (مُصحَّح في v2.81)
./mediamtx --version                # تحقّق: v1.21.1
```

> **[v2.81·تصحيح أمرين كانا لا يُنفَّذان]** رابط
> `releases/latest/download/mediamtx_linux_arm64v8.tar.gz` **يعيد 404 اليوم**:
> التسمية تغيّرت فصارت `mediamtx_<الإصدار>_linux_arm64.tar.gz` (بلا `v8`
> وبإصدار داخل الاسم). وثانياً `~/mediamtx` غير موجود على هذا المضيف أصلاً، فالأمر
> كان يفشل عند أول سطر.
>
> **ولا تشغّلوا `./mediamtx` في المقدمة ولا بـ`nohup … &`:** العملية بلا مشرف
> لا تعود بعد إعادة تشغيل الجهاز. المشرف المتاح فعلاً هو **pm2**
> (`pm2 start /root/mediamtx/mediamtx --name mediamtx && pm2 save`) — **وليس
> systemd**، إذ لا يدير المضيف العمليات بـsystemd أصلاً. التفاصيل في
> `docs/PHONE_HANDOFF_v281.md` §2.3.

**تفعيل النظام (متغيرات بيئة الخادم — `.env.local` ثم `bash scripts/phone-env-restart.sh`):**
```bash
MEDIAMTX_WHIP_URL=http://127.0.0.1:8889   # عنوان WHIP (نفسه يخدم WHEP)
ARB_STUN_URLS=stun:stun.l.google.com:19302,stun:stun1.l.google.com:19302
# [v2.81] المراقبة ومشاركة شاشة الهاتف (راجع §8 و§9):
MEDIAMTX_API_URL=http://127.0.0.1:9997    # افتراضي — لا يلزم كتابته إن لم يتغيّر
MEDIAMTX_RTMP_URL=rtmp://<عنوان-النفق-العام>:1935   # نشر شاشة الهاتف من الخارج
```

> **[v2.81·تصحيح ادّعاء] `MEDIAMTX_WHIP_URL` ليس «موجوداً منذ v2.78» على هذا
> المضيف.** سطر الدليل القديم كان يعرضه ضمن «القائمة (كانت موجودة من v2.78 —
> لا تغيير)»، والفحص على `.env.local` (2026-10-03) يعطي **صفر متغيّر يبدأ بـ
> `MEDIAMTX`** و**صفر يبدأ بـ`ARB_STUN`** — لا `MEDIAMTX_WHIP_URL` ولا
> `MEDIAMTX_API_URL` ولا `MEDIAMTX_RTMP_URL`.
> ⇒ **احتياطي WHIP (v2.75) لم يتفعّل على هذا الجهاز قط.** **وهذا سليم:** النظام
> يعمل الآن بوضع **P2P حصراً** (WebRTC مباشر بين اللاعبين — بلا مرحّل وبلا أي
> متغيّر)، فهو المسار الأساسي وهو ما تعمل عليه اللوحة فعلياً. المرحّل كله
> *احتياطي اختياري*؛ وغيابه لا يُعطّل البث ولا الحساب ولا المال — إنما يظهر في
> لوحة الأدمن شريحة **«⚫ المرحّل لا يرد»** بدل سطر الحالة (§8.4). إن ثُبِّت
> المرحّل ورغبتم في تفعيل WHIP ⇒ أضيف السطر أعلاه ثم `phone-env-restart.sh`.

بدون `MEDIAMTX_WHIP_URL` يعمل النظام بوضع P2P حصراً (المحاولتان ثم فشل نظيف — لا مرحّل) — **وهذه هي الحالة الفعلية لهذا المضيف اليوم.**

**الدقة والخفة:** لا ترميز في MediaMTX (ترحيل فقط) — العميل يلتقط أصلاً بقيود خفيفة في `getDisplayMedia` (15–24 إطاراً و1280×720 كحد أقصى في arb-client.js — عدّلها لـ854×480 لمزيد من الخفة). إن أردت ترميزاً قسرياً 480p/720p أضفه في `mediamtx.yml` (وفّر المعالج — لا يُنصح به على هذا الهاتف).

### 5.1 المسارات — كتلة `~^dtsg` [v2.81]

**[v2.81] المفتاح في `mediamtx.yml` تعبير نمطي `~^dtsg:` لا اسم حرفي `dtsg/`**،
لأنه يجب أن يغطي صيغتي النشر معاً — وإلا صار أحدهما خارج التغطية:

| الصيغة | من ينشرها | مفتاح `~^dtsg` يغطّيها |
|---|---|---|
| `dtsg/<roomId>/<playerId>` | تطبيق RTMP على الهاتف عند مشاركة الشاشة (§9) | ✅ |
| `dtsg-<roomId>-<userId>` | **الاحتياطي WHIP** — وهو ما ينشره `js/core/arb-client.js` فعلياً: السطر 227 يبني `roomId` + `-` + معرّف اللاعب (و`p` إن لم يكن محمّلاً)، ثم السطر 239 ينشره على `/whip/dtsg-` + ذلك | ✅ |

**لماذا تغيّر الاسم [v2.81]؟** إعداد لم يكن MediaMTX v1.x يستطيع إقلاعه أصلاً،
ولم يُكتشف لأن الثنائي لم يكن مثبَّتاً على الهاتف قط:
1. `dtsg/` — و`IsValidPathName` (internal/conf/path.go) ترفض أي اسم مسار ينتهي
   بشرطة مائلة ⇒ **الخادم يمتنع عن الإقلاع**.
2. `fallback: present` — وحقل `fallback` في v1.x حقل **إعادة توجيه** (redirect)
   لا يقبل إلا مساراً أو عنوان RTSP صالحاً ⇒ السلسلة `present` تُفشل التحقق.
   والمقصود أصلاً «يقبل هذا المسار من ينشر إليه» هو `source: publisher` وحدها،
   فحُذف السطر.

> ولا يُنهَ المفتاح أبداً بشرطة مائلة (`~^dtsg/`) — الشرطة الذيلة تُخرجه من
> دائرة التعابيرية فيعود رفض `IsValidPathName` نفسُه.

### 5.2 ⚠️ بند مفتوح — لا مصادقة نشر على `~^dtsg` (يحتاج قرار المالك)

كتلة المسارات هذه **بلا أي مصادقة نشر**: الحقلان `publishUser` و`publishPass`
مهجوران. فكل من يصل إلى منفذ RTMP (1935) — أي منفذ كشفتموه للعالم (§9) —
يستطيع النشر في `dtsg/<أي غرفة>/<أي لاعب>`، ولا يُمَنع من ذلك شيء.

ولا يصحّ الاعتماد على ظاهر المسار بوصفه مفتاحاً سرّياً: `roomId` و`userId`
أرقام صغيرة، و`roomId` هو نفسه رمز غرفة التحكيم المفتوحة في لوحة الأدمن —
**فالتخمين عمليّ**.

**الأثر — وهو ما يستحق قرار المالك:** نقطة `GET /api/matches/:roomId/stream-status`
(§8.1) تستند إلى «المسار جاهز» دليلاً على أن **هذا اللاعب بعينه** يبث، فنشرٌ
من خارج الهاتف قد **يوهم الأدمن بأن لاعباً يبث وهو صامت**، والحسم قرار
سوبر-أدمن **يُفرج عن الإيداعات** (قاعدة 17). المراقبة نفسها لا تكتب مالاً —
لكنها **تغذّي قراراً مالياً** — ولهذا يستحق الغلاف قراراً صريحاً.

| الخيار المرشّح | الفكرة | ما الذي يتغيّر |
|---|---|---|
| **أ) توكن جلسة غير قابل للتخمين** | توكن عشوائي لكل جلسة تحكيم يُدمج في المسار (`dtsg-<room>-<user>-<token>`) | توليد المسار في الواجهة + تحقّق إضافي في `server-mediamtx.js` قبل قبول «جاهز» |
| **ب) مصادقة داخلية لـMediaMTX** | `authInternalUsers` بقيد نشر على `~^dtsg` وسرّ مشترك | سرّ في `mediamtx.yml` خارج المستودع + إسناد `publishUser`/`publishPass` |

**لم يُطبَّق أيٌّ منهما — توثيق وطلب قرار فقط.** حتى يُقرّر المالك: لا تُخرجوا
1935 للعالم إلا عند الحاجة، وأوقفوا النفق فور انتهاء الاختبار. (نفسه في
`docs/PHONE_HANDOFF_v281.md` §4 بند 3.)

**تنبيه شبكة:** MediaMTX على الهاتف يستمع محلياً — وصول الأدمن إليه من الخارج يتطلب توجيه مسار النفق إليه (مسار Cloudflare Tunnel إضافي نحو `127.0.0.1:8889`) أو حصر المشاهدة عبر المرحّل على شبكة الهاتف/VPN. أبقِ P2P هو المسار الأساسي؛ المرحّل احتياطي.

## 6. التكامل مع قاعدة SQLite الحالية

- الجدول الجديد `arb_sessions` يُنشأ تلقائياً في نفس قاعدة المنصة (`data/royalcoin.db`) — بلا أي هجرة يدوية.
- الحسم لا يكتب مالاً جديداً: صفوف `win`/`refund` وسجل `transactions` وتذاكر `bet_tickets` تُنشأ من نواة التسوية المعتمدة نفسها (راجع `docs/MONEY_CONTRACT_ROOMS.md`).
- استعلامات التدقيق:
```sql
SELECT * FROM arb_sessions ORDER BY id DESC LIMIT 50;
SELECT * FROM transactions WHERE meta LIKE '%تحكيم%' ORDER BY ts DESC;
```

### 7.1 متطلبات مشاركة الشاشة [v2.78] — رسائل دقيقة بلا تضليل

بلاغ المالك الموثق: «رسالة تقول إن المتصفح لا يدعم مشاركة الشاشة مع أنه كروم» —
الجذر ليس عطلاً في الكود بل غياب تمييز الأسباب؛ كروم **يحجب** واجهة البث في
حالتين شائعتين، و`arb-client.js` صار يفصل بينهما برسالة صحيحة لكل حالة:

| التشخيص (`ARB.support()`) | الشرط الفعلي | الرسالة |
|---|---|---|
| `insecure` | فتح المنصة عبر `http://` غير المحلي — كروم يحجب `navigator.mediaDevices` كلياً | «تتطلب اتصالاً مشفراً HTTPS — افتح المنصة عبر رابطها الرسمي» |
| `mobile` | متصفح هاتف (كروم أندرويد / WebView / متصفحات التطبيقات): `mediaDevices` موجودة و`getDisplayMedia` غائبة — **قيد منصّي في كل متصفحات الجوال، لا عطب** | «متصفح الهاتف لا يدعم مشاركة الشاشة — افتح المنصة من حاسوب (كروم/إيدج/فايرفوكس)» |
| `old` | متصفح مكتبي قديم (كروم < 72) | «حدّث متصفحك إلى أحدث إصدار» |
| `ok` | الواجهة متاحة | زر البث الذهبي المعتاد |

- الزر نفسه يتحول إلى وضع تحذيري (⚠️ غير متاحة هنا) مع الشرح داخل الصندوق —
  داخل مودال الغرفة وصفحة `#arb` معاً، فلا يفاجأ اللاعب بعد النقر.
- أخطاء الالتقاط صارت مصنفة كذلك: `NotAllowedError` (رفض الإذن)،
  `NotReadableError`/`AbortError` (الشاشة مشغولة ببرنامج تصوير آخر)،
  و`OverconstrainedError` (إعادة محاولة تلقائية بقيود مجردة).
- **الخلاصة التشغيلية للاعبين:** البث من **حاسوب** بمتصفح حديث عبر **HTTPS**
  حصراً؛ مراقبة الأدمن تعمل من أي جهاز (لا تلزمها واجهة الالتقاط).

**الاختبارات:** `QA_BASE=http://127.0.0.1:3971/ node tests/_v275_arbitration_test.js` — 30/30 فحصاً (REST + حراسة + إشارات + حسم/نزاع + بث P2P حقيقي حتى ظهور الفيديو عند الأدمن). ملاحظة بيئة: `getDisplayMedia` في المتصفحات بلا واجهة يفشل — الجنحة تستبدله بمجرى Canvas تركيبي لنفس مسار WebRTC الحقيقي.

## 8. مراقبة حالة بث المرحّل [v2.81] — MediaMTX Status Monitoring

طلب المالك (مستند «ربط MediaMTX API بالباكأند»): أن يعرف الباكأند لحظة
استعلامه هل اللاعب يبث فعلاً عبر المرحّل أم انقطع بثّه — لحسم التحكيم على
أساس حقيقي لا افتراضات، **بثلاثة قيود صارمة مُنفَّذة حرفياً** في وحدة
`server-mediamtx.js` الجديدة:

| القيد من المستند | التنفيذ |
|---|---|
| **صفر باندويث عبر النفق** | الاستعلام عبر Loopback حصراً (`MEDIAMTX_API_URL` افتراضه `http://127.0.0.1:9997`) — عنوان غير محلي ⇒ تحذير تمريري في السجل (عزل تام، لا انهيار) |
| **استعلام عند الطلب حصراً** | لا حلقات تكرار ولا مؤقتات خلفية إطلاقاً — يُستعلم MediaMTX فقط عند نداء نقطة النهاية (أدمن فتح لوحة المباراة) + كاش ثانوي 1.5ث يمتص تكرار عدة لوحات |
| **عزل تام وتراجع آمن** | توقف MediaMTX ⇒ `available:false` وحالة offline فورية بلا أي أثر على الخادم أو قاعدة البيانات + تحذير مقتضب مهدَّد (مرة كل دقيقة كحد أقصى) |

### 8.1 نقطة النهاية (أدمن/سوبر حصراً)

`GET /api/matches/:roomId/stream-status` — تفحص بثّي «اللاعب A» و«اللاعب B»
محلياً (أول مقعدين في ترتيب الغرفة) وتعيد JSON خفيفاً بالشكل الذي طلبه المستند:

```json
{
  "ok": true, "match_id": "101", "available": true,
  "watch_timeout_ms": 30000, "session_live": true,
  "player_a_status": { "user_id": 7, "username": "adil", "online": true, "ready": true, "bytes_rx": 5242880, "stream_duration": 95, "path": "dtsg/101/7", "offline_since": null, "alert": false },
  "player_b_status": { "user_id": 12, "username": "tarik", "online": false, "ready": false, "bytes_rx": 0, "stream_duration": 0, "path": "dtsg-101-12", "offline_since": 1730000000000, "alert": true },
  "arbitration_ready": false
}
```

- **منطق المسارات:** يُفحص النمطان الموثّقان معاً — `dtsg/<roomId>/<userId>`
  (مسار RTMP لنشر شاشة الهاتف §9) و`dtsg-<roomId>-<userId>` (مسار WHIP الفعلي
  الصادر من `arb-client.js`) — أول مسار جاهز (`ready:true`) هو الحكم. كتلة
  المسارات التي يستجيب لها المرحّل هي `~^dtsg` (انظر §5.1).
- **الحراسة:** 401 بلا جلسة · 403 لغير الأدمن · 404 غرفة مجهولة.
- **[v2.81·انزياح حقول API — مُصلَح]:** الوحدة كانت تقرأ `ready` و
  `bytesReceived` وحقل `readyDuration`. الحقلان الأولان **ما زالا يُبَثّان
  لكنهما مهجوران**، و`readyDuration` **حُذف** من الإصدارات الحديثة وحلّت
  محلّه تواريخ RFC3339. والنتيجة: حالة البث كانت تُقرأ `false` على أي مرحّل
  حديث رغم أن البث قائم. الآن تُقبل الصيغتان معاً:
  `online`/`inboundBytes` المعتمدان اليوم، و`readyTime`/`onlineTime` للمدة.
- **[v2.81·إصلاح تعليق — مُصلَح]:** طلب HTTP إلى المرحّل كان **لا يستدعي
  نداءه الراجع إطلاقاً** إذا قطع المرحّل المقبس في منتصف الجسم (لا `end` ولا
  `error`) ⇒ طلب الأدمن يعلق إلى الأبد، ومع `maxSockets:4` المشترك يتجمّد
  الاستعلام **لكل الغرف** على المنصة كلها لا لغرفة واحدة. الآن النداء الراجع
  ينحسم **مرة واحدة على كل طريق** (`error` · `aborted` · `timeout` · حارس زمني
  مُصفَّر عند الحسم) — **بلا حلقة خلفية** ⇒ القيد 2 أعلاه يبقى قائماً.
- **[v2.81·لا مال · مُتحقَّق منه ساكناً]:** لا `UPDATE`/`INSERT`/`DELETE` على
  `users`/`transactions`/`rounds`/`bet_tickets`/`refunds` في الوحدة إطلاقاً —
  والمكتوب الوحيد هو `arb_stream_events` (سجل تدقيق، بلا رصيد).

### 8.2 تنبيه الانقطاع (>30ث) — «دون تعديل الرصيد تلقائياً»

بالذاكرة لكل (غرفة×لاعب)، والاستعلام على الطلب يعني أن لوحة مفتوحة (استطلاع
10ث) تكشف الانقطاع فور تجاوز مهلة المراقبة، ولوحة مغلقة لا تستهلك شيئاً:

1. **انقطاع لمن سبق له البث** أثناء جلسة حية ⇒ يُثبَّت `offlineSince`؛ تجاوز
   `MEDIAMTX_WATCH_TIMEOUT_MS` (افتراضه 30ث) ⇒ **تنبيه واحد لكل نوبة**:
   صف في SQLite (`arb_stream_events` — للتدقيق حصراً) + حدث SSE **`arb:stream`**
   للأدمن/السوبر حصراً + toast 🚨 في لوحة التحكيم.
2. **العودة** ⇒ حدث `recovered` بصفه وtoast 🟠.
3. **من لم ينشر قط لا يُنذر** (الانقطاع لمن سبق له البث حصراً — لا إنذار كاذب
   لمن لم يبدأ).
4. **لا يُمسّ أي رصيد مهما حصل** — القرار النهائي للأدمن حصراً (نص المستند حرفياً).

### 8.3 تفعيل المراقبة (خطوتان على خادم الهاتف)

### 8.4 ما يظهر عند الأدمن

سطر حالة تحت فيديو كل لاعب في المشاهدة المزدوجة (استطلاع 10ث + أحداث SSE):
`🟠 المرحّل مباشر · 3.0MB · 1:35` عند البث، و`🚨 انقطع عبر المرحّل (2د)` بعد
تجاوز المهلة — والشريحة تُحدَّث في مكانها بلا مسّ للفيديوهات (نمط بوابة
التوقّع v2.77 — لا وميض).

**[v2.81] حالة رابعة — «المرحّل لا يرد»:** كان `available:false` (المرحّل
ميت أو غير مركّب) يُخزَّن ولا يُعرض، فصار **«المرحّل مطفي» و«اللاعب سكت» شيئاً
واحداً** في عين الأدمن — وهي بالضبط الحالة التي قد يبنى عليها قرار حسم. الآن
تُرسم شريحة صريحة **`⚫ المرحّل لا يرد`** (مفتاح i18n جديد `arb.relayDown`
مترجم ×4) متى رجع `available:false`، وتعود لحالتها السابقة تلقائياً أول ما
يستجيب الاستطلاع. لا تمسّ الفيديو ولا تُعيد رسم المشاهدة.

## 9. مشاركة شاشة الهاتف — البديل التقني [v2.81]

**الجذر:** متصفحات الجوال كلها (أندرويد/iOS) لا توفّر `getDisplayMedia` —
قيد منصّي لا حلّ برمجياً داخل المتصفح (توثيق v2.78 §7.1). **البديل المعتمد
بتوجيه المالك:** اللاعب يبث شاشة هاتفه بتطبيق بث RTMP مجاني (مثل **Larix
Screencer**) إلى MediaMTX على خادم المنصة، والأدمن يشاهده عبر المرحّل نفسه —
دون أي حاسوب وضمن المنظومة القائمة دون تعديل معماري.
**[v2.81·تصحيح]:** عبارة «الموجود أصلاً» الواردة في صيغة سابقة من هذا القسم
كانت خاطئة — المرحّل **غير مثبَّت** على خادم الهاتف اليوم (§5)، فالأدق أن
يُقرأ: إلى MediaMTX على خادم المنصة **بعد تثبيته**.

**تدفق البث من الهاتف:**
```
تطبيق RTMP على الهاتف (Larix Screencer)
   → rtmp://<عنوان-عام>:1935/dtsg/<roomId>/<userId>   (MEDIAMTX_RTMP_URL)
   → MediaMTX على خادم الهاتف (استقبال RTMP — ترحيل بلا ترميز)
   → الأدمن يشاهد عبر WHEP/WebRTC في لوحة التحكيم (المشاهدة المزدوجة المعتادة)
```
مسار النشر يحمل **معرّف غرفة اللاعب ومعرّفه** (لا سرّ فيه — انظر التحذير
أدناه)، وتعرضه المنصة في صفحة **التحكيم المباشر** (`#arb`) ببطاقة إرشادية
«📱 مشاركة شاشة الهاتف» تظهر **للاعب على هاتف حصراً** (reason === 'mobile')
مع زر 📋 نسخ — ومشاركة المتصفح من حاسوب تبقى كما كانت بلا مساس (المكتسبات).

> ⚠️ **لا يُعتمد على المسار بوصفه سرّياً [v2.81]:** الصيغة أعلاه مكشوفة التخمين
> (معرّفات صغيرة + رمز الغرفة ظاهر في لوحة الأدمن)، ولا مصادقة نشر على كتلة
> `~^dtsg`. البند مفتوح ويحتاج قرار المالك — **§5.2**. فالكرة هنا تشغيلية
> فقط، فلا تُبنَ عليها سياسة أمان حتى يُقرّر.

**ما نفّذته المنصة (جهة الويب — مكتمل):**
- `server-arbitration.js`: بيانات المرحّل في `/api/matches/mine` (`relay.rtmp`) والتوكن (`mediamtx_rtmp`) — بلا أسرار: العنوان العام يبنيه المالك في `.env.local`.
- `arb-page.js`: البطاقة الإرشادية (خطوات ×4 لغات + نسخ العنوان) + الزر يبقى وضعاً تحذيرياً ⚠️ على الهاتف ولا تُمحوه شريحة الحالة.
- `arb-client.js`: سطر تلميح «البديل على الهاتف» داخل مودال الغرفة.
- `arb-admin.js` + `server-mediamtx.js`: سطر حالة المرحّل وتنبيه الانقطاع/العودة (§8).
- i18n: مفاتيح `arb.mr*` التسعة مترجمة ×4 (عربية/فرنسية/إنجليزية/دارجة).

**ما يلزم على خادم الهاتف (جهة المسؤول ومساعديه):** تثبيت MediaMTX وتشغيله
تحت pm2 (§5) + توجيه منفذ RTMP 1935 عبر نفق عام + ضبط `MEDIAMTX_RTMP_URL` +
تحديث `mediamtx.yml` وإعادة التشغيل — الخطوات كاملة بالأوامر والتحققات في
**`docs/PHONE_HANDOFF_v281.md`**.

**الاختبار:** `QA_BASE=http://127.0.0.1:3971/ node tests/_v281_mediamtx_status_test.js`
— **53/53** فحصاً (كان 47/47 قبل تدقيق v2.81). وحدة المراقبة بمرحّل وهمي
(جاهز/مفقود/نمطا المسارين/تعطُّل API/تنبيه 30ث وعودته) + REST على خادم QA +
فحوص ساكنة (yml/workflow/gitignore/redirects/الدليل).
**[v2.81 تدقيق]** أُضيفت تغطية كانت باطلة أو غائبة: نصف شرط `sessionLive`
